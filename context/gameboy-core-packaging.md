# Research: Game Boy/GBC libretro core packaging

## Summary
SameBoy is the cleanest core to bundle in a Rust app/plugin because its libretro core is MIT-licensed; include the MIT notice and pin the source/build used. Gambatte can also be redistributed as a binary, but it is GPLv2, so bundling it creates GPL compliance obligations and possible copyleft risk for a proprietary/non-GPL host; prefer user-installed/downloaded Gambatte unless the project is comfortable with GPL handling.

## Findings
1. **Expected Linux core filenames are stable and conventional.** Gambatte's libretro Makefile sets `TARGET_NAME := gambatte` and, on Unix, builds `gambatte_libretro.so`; SameBoy's libretro Makefile sets `TARGET_NAME = sameboy` and, on Unix, builds `sameboy_libretro.so`. Libretro core metadata uses matching `gambatte_libretro.info` and `sameboy_libretro.info`. [Gambatte Makefile](https://github.com/libretro/gambatte-libretro/blob/master/Makefile.libretro), [SameBoy Makefile](https://github.com/libretro/SameBoy/blob/master/libretro/Makefile), [Gambatte info](https://github.com/libretro/libretro-core-info/blob/master/gambatte_libretro.info), [SameBoy info](https://github.com/libretro/libretro-super/blob/master/dist/info/sameboy_libretro.info)
2. **SameBoy binaries are practically redistributable.** The libretro/SameBoy repository is MIT licensed, expressly permitting copying, distribution, sublicensing, and sale, provided the copyright/license notice is included. This makes it the preferred bundled default for a Rust app/plugin. [SameBoy LICENSE](https://github.com/libretro/SameBoy/blob/master/LICENSE)
3. **Gambatte binaries are redistributable, but GPLv2 compliance is required.** Gambatte's core metadata says `license = "GPLv2"`, and the repository includes GPLv2 terms permitting object-code distribution only with corresponding source, a written source offer, or equivalent source-access information. If bundled, ship GPL text/notices and exact corresponding source/build scripts; if the host is not GPL-compatible, get legal review or avoid bundling. [Gambatte info](https://github.com/libretro/libretro-core-info/blob/master/gambatte_libretro.info), [GPLv2 COPYING](https://github.com/libretro/gambatte-libretro/blob/master/COPYING)
4. **System-installed Linux cores are commonly under `/usr/lib/libretro`; per-user RetroArch cores are commonly under `~/.config/retroarch/cores`.** ArchWiki documents system core path `/usr/lib/libretro`, info path `/usr/share/libretro/info`, and per-user core path `~/.config/retroarch/cores`; it also notes RetroArch can download per-user cores via the libretro Buildbot or install system-wide cores via packages. [ArchWiki RetroArch](https://wiki.archlinux.org/title/RetroArch), [Libretro directory docs](https://docs.libretro.com/guides/change-directories/)
5. **Official Buildbot binaries exist, but nightly single-core URLs are mutable.** The libretro Buildbot currently publishes Linux x86_64 zip files named `gambatte_libretro.so.zip` and `sameboy_libretro.so.zip` under `nightly/linux/x86_64/latest/`; stable releases expose large `RetroArch_cores.7z` archives rather than obvious single-core stable zips. For reproducible redistribution, prefer self-built pinned binaries or a stable archive with recorded checksums; for fallback, download on user consent into an app-owned cache and verify SHA-256. [Nightly x86_64 listing](https://buildbot.libretro.com/nightly/linux/x86_64/latest/), [Stable x86_64 listing](https://buildbot.libretro.com/stable/1.22.0/linux/x86_64/)
6. **Clean fallback approach:** discovery order should be: user-configured core path; app-managed cache such as `$XDG_DATA_HOME/<app>/libretro/cores`; system paths such as `/usr/lib/libretro` and `/usr/local/lib/libretro`; optional RetroArch user path `~/.config/retroarch/cores`. If missing, prompt the user to install via distro packages where available, select a local `.so`, or download `sameboy_libretro.so.zip`/`gambatte_libretro.so.zip`; never silently write to RetroArch/system directories. RetroArch docs note some package-manager installs disable core downloading and require package-manager installation instead. [Installing cores docs](https://docs.libretro.com/guides/download-cores/), [ArchWiki RetroArch](https://wiki.archlinux.org/title/RetroArch)
7. **Do not bundle Nintendo BIOS/boot ROMs.** Both core info files list optional firmware/BIOS names and checksums, meaning a frontend can run without bundling copyrighted Nintendo BIOS files and should let users provide them if desired. [Gambatte info](https://github.com/libretro/libretro-core-info/blob/master/gambatte_libretro.info), [SameBoy info](https://github.com/libretro/libretro-super/blob/master/dist/info/sameboy_libretro.info)

## Gaps
No explicit Buildbot redistribution policy page was found; redistribution rights appear to come from each core's license. For shipping binaries, pin exact commits, keep source archives/checksums, and have counsel review GPL implications if choosing Gambatte.
